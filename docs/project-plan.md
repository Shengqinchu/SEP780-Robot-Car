## 这一版做什么

- 单条黑线和宽缓弯道循迹，不处理交叉路口选路。
- 遇障停车等待，不主动规划绕行；恢复需持续有效回波与有效线型。
- 障碍仍在停止阈值内时使用板载蜂鸣器短促提示，移开后停止鸣叫并进入恢复确认。
- 手动控制使用油门/转向差速混合、死区、响应曲线和加减速限制；松手、过期或 STOP 都归零。前方障碍阻止继续前进，但允许倒车或原地转向脱离。
- App 可长按手动鸣笛；板载有源蜂鸣器只能形成节奏提示，不能演奏可辨音高的旋律。
- 无回波、读数过期、低电压和错误指令退出运行模式。
- 可以通过红外独立运行，或通过有期限的电脑串口会话调试。
- 安卓 App 通过套件 BLE 模块发送同一协议；语音只映射为停止、循迹和四个限时方向动作。App 的摇杆可选上限为 110–180、默认 150，只控制手动/语音方向；循迹独立使用车端 PWM 120、80 ms 驱动 / 80 ms 滑行脉冲。
- 调试数据落为 JSONL/CSV，离线场景直接测试生产 C++ 逻辑。

完整行为见[控制程序](controller.md)，到货步骤见[校准指南](calibration.md)。

## 当前最短实车路径

不逐个重复全部原厂示例。正式固件离线验证完成后，只用三道综合门槛推进：

1. 架空上电：确认转头归中、轮子默认不动，并读取电池、循迹和测距状态。
2. 架空短动：每个方向最多约 1 秒，确认四轮极性、停车和蜂鸣器，不做长时间空转。
3. 地面低速：先短距离循迹，再加入前方障碍，确认停车、短鸣、移开后恢复。

完整 15 项清单用于最终证据和报告，不是开始最终项目之前必须逐项完成的前置实验。任一综合门槛暴露异常时，才退回对应单项诊断。

工具调研见 [tooling-research.md](tooling-research.md)。已采用 Arduino CLI、pySerial 和 Unity；Zig 用来在 Windows/Linux 编译同一份 C++ 测试代码。没有安装第三方 MCP，也没有引入不使用的调度框架。
