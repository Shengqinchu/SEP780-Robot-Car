## 先说结论

项目的软件功能已经齐全，可以进入演示准备。新版手机遥控与鸣笛已经装机，用户带电综合操作反馈总体可用；偶发 `command rejected` 作为已知问题保留。正式展示前还要在固定白底黑线场地完成两道证据门槛：

1. 中文或英文语音在真车上完成停止、限时方向动作和启动循迹；
2. 正常循迹档以直线 PWM 120、转弯 PWM 150 在同一条完整路线至少重复五次，并记录每次成功、失败原因和证据。录像彩排中若再次出现拒绝指令，同时保存 App 状态、ACK 和遥测。

课程资料确认 `Project Presentation and Report` 占总评 35%，学习计划把 `Demo and Report` 安排在 2026 年 12 月 3 日所在周。现有本地资料没有给出演示时长、报告篇幅或更细 rubric；下面按录像 demo 准备，最终时长、格式和提交附件以 Avenue 公告为准。

## 演示要证明什么

录像不需要把每个测试重新跑一遍。用一条连续主镜头和 App 近景证明五件事：

| 目标 | 现场证据 |
| --- | --- |
| 安全启动 | 上电后轮子不动，连接后左右输出仍为 0 |
| 手机控制 | 蓝牙状态变蓝，手机能看到电池、距离和三路循迹状态 |
| 赛车式遥控 | 摇杆可连续控制油门和转向，松手归零；速度上限和手动鸣笛可见可用 |
| 语音控制 | 有限中英文命令被转换为有时限的安全指令 |
| 自主循迹与避障 | 沿黑线行驶，20 cm 内停车并短鸣，移至 30 cm 外持续 600 ms 后恢复 |
| 故障安全 | 脱线、歧义线型、失联、低压或无有效测距时不继续盲走 |

遥测中的左右 PWM 是控制器请求值，不是编码器测得的轮速；演示时不要把它说成实际速度反馈。

## 场地怎么搭

### 推荐布局

- 使用哑光白色海报纸、泡沫板或白色桌面，中央贴单条哑光黑线。
- 先做一段不短于车身两倍的直线，再接一个宽缓弯道；不做交叉口、锐角或主动绕障。
- 在第二段直线上预留障碍区。用平整、能反射超声波的竖直纸板作为障碍，不用手长期挡在车头前。
- 起点放在直线中央，三个循迹探头应得到中央黑线 `010`；终点前留出停车空间。
- 避免阳光直射、强反光胶带、木纹底面和悬空边缘。整条路线先用静止遥测检查，不能只凭肉眼判断黑白对比。

```text
              障碍区
                [#]
                 |
起点 ========\     /======== 终点
              \___/

白色底面；黑线；一个宽缓弯；障碍放在直线段
```

车头无障碍时也要有稳定的有效回波，范围为约 30 cm 至 4 m。若场地太空旷而持续无回波，主控会按设计停车；应调整路线朝向或增加远处平整背景板，而不是关闭传感器故障保护。

### 器材

- 充满且外皮完好的两节 18650 电池和配套电池盒；
- 已安装 SEP780 App 的 Android 手机；
- 原厂红外遥控器，作为蓝牙失联时的备用停止工具；
- 白色底板、黑色哑光胶带、平整障碍物；
- 手机支架或第二台手机，用于连续录像；
- USB 数据线和电脑只作为现场恢复工具，不拖线运行小车。

## 录像怎么做

### 录制前 10 分钟

1. 把小车放在起点并关闭两个电源开关；检查电池、轮胎、舵机固定螺丝、蓝牙模块方向和所有插头。
2. 清理路线，固定黑线和障碍位置；在相同灯光下先完成一次不录像的完整预跑。
3. 手机关闭省电限制和勿扰干扰，保持屏幕常亮；确认蓝牙、附近设备和麦克风权限可用。
4. 选择一种界面语言后再连接小车。连接中切换语言会先停止并断开蓝牙，不把它安排在运动过程中。
5. 上电，通过只开关本车蓝牙电源的差分扫描确认并连接目标模块；确认连接灯为蓝色、左右输出为 0、距离和三路循迹数据合理。
6. 手动速度上限选择已验收档位；App 默认 150，可在 110–200 调整。循迹不由该滑杆控制：中线使用车端 PWM 120 脉冲，正常档转弯使用 150。
7. 先按一次固定“停止”键，再开始讲解。另一名组员站在物理开关旁，但手不伸进运动区域。

### 推荐分工

| 角色 | 工作 |
| --- | --- |
| 讲解员 | 按下面稿子讲目标、改进、结果和局限 |
| 操作员 | 连接手机、发语音命令、放置/移除障碍、执行停止 |
| 记录员 | 连续录像、计时并填写五次运行表；两人组时由讲解员兼任 |

不要让三个人同时碰车。任何人喊“Stop”时，操作员先按 App 停止；没有响应就按红外 `0`，再关闭物理电源。

## 常见提问的短答案

**和原厂有什么区别？**
原厂硬件保留不变；项目把循迹、避障、故障停车、双语手机控制、语音、遥测和可重复测试整合到统一协议和状态机中，并记录了本车的方向、舵机中位和最低可靠 PWM 校准。

**为什么不做主动绕障？**
当前只有一个朝前的超声波测距，缺少可靠的侧后方环境信息。停车、报警并在确认安全后恢复，比盲目绕行更符合现有传感器能力。

**为什么选择白底黑线？**
这组三路数字反射传感器只能输出黑白阈值。木纹与黑线可能产生相同二值，软件无法恢复已经丢失的光学对比；白色哑光基准更可重复。

**语音失误会不会一直跑？**
不会。未知词不发送运动，停止词优先，方向动作约一秒自动停止，循迹需要持续心跳，断连后车端租约超时停车。

**手机显示的是实际轮速吗？**
不是。左右数值是控制器请求的 PWM。当前没有轮速编码器，因此报告中不会把它写成闭环速度测量。

**为什么 App 能选到 PWM 50？**
这是保留的手动实验范围。实车已经证明 50–100 不能可靠起步，所以循迹中线固定使用 PWM 120；步进为 80/80 ms，正常档只在侧偏或单侧位时使用连续 PWM 150。协议接受数值不等于电机一定转动。

## 失败时怎么恢复

| 现象 | 现场动作 | 对老师的说明 |
| --- | --- | --- |
| 语音未识别 | 先按停止，再用屏幕按钮或红外继续 | 未得到合法词时系统按设计不发送运动 |
| 蓝牙断开 | App 停止，红外 `0`，重新连接后确认左右输出为 0 | 通信租约失效会在车端停车 |
| 小车不启动 | 不连续重复 ARM；检查距离、线路、电池和状态 | 安全门槛未满足时启动会被拒绝 |
| 手动低档单侧或双侧不起转 | 立即停止，使用事先验收的手动上限；不要把摇杆上限误认为循迹速度 | 起转门槛受电池、负载和电机差异影响 |
| 脱线 | 停止后把车放回起点，检查白底、黑线和光照 | 数字循迹传感器需要稳定反射对比 |
| 遇障后不恢复 | 保持停止，检查障碍已超过 30 cm、线路有效且回波稳定 | 恢复包含距离迟滞和 600 ms 持续确认 |
| 任意失控迹象 | App 停止 -> 红外 `0` -> 关闭两个电源开关 | 不继续解释或伸手抓动车轮中的小车 |

现场失败不等于必须掩盖。安全停止本身就是设计结果；简短解释触发了哪一条安全门槛，再使用已录制的连续成功视频补充即可。
