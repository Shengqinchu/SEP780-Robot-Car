# 验证清单

当前已完成主控 USB 实测、舵机接线修复、82 度初步中位、BLE 遥测和旧四向遥控架空输出。PWM 50–100 不能可靠起步。同路线 A/B 已确认步进档在急弯卡住，全连续档则直线过快并冲出黑线；正常混合版把中线保持为 PWM 120 的 80/80 ms 步进，并用 PWM 150 连续修正转弯。2026-09-21 的固件与摇杆 App 已刷入 COM5、安装到 Redmi，用户带电操作反馈总体可用；偶发 `command rejected` 尚未定位。用户后来报告同一白底黑线场地测试 5 次、均正常；提供的单段录像可见小车沿路线移动和旧圆盘 App 连接，但无法单凭画面核实五次独立完整路线、逐次障碍/语音结果或新版摇杆操作。新改的 App 可选上限为 110–180，默认 150；固件协议仍接受 200，电机 I/O 截断到 180。该 APK 已通过 17/17 Android 单测与 Lint，但尚未安装到手机或实车验收。未提供失败时 ACK/遥测，故不把 `command rejected` 标记为已修复。

## 当前执行顺序

先走三道综合门槛：架空上电读取状态、架空每方向最多约 1 秒短动、地面低速循迹加障碍。下方 HW-01 至 HW-15 是最终报告的完整证据清单，不要求在开始正式固件前逐项运行；只有综合测试失败时才拆回单项排查。

## 软件覆盖

- 控制器：默认零输出、模式与控制来源、原子串口遥控接管、五种有效线型、80/80 ms 步进、正常档中线步进/侧偏连续/单侧原地转向、档位权限、红外恢复步进、各档停车联锁、手动前进障碍限制与倒车脱离、蜂鸣租约、恢复重启相位、障碍迟滞、过期/无效读数、电压检查和计时回绕。
- 命令：固定长度缓冲、紧凑 `R`/`H` 帧、分帧、CRLF、超长输入、非 ASCII、坏数字、超时后丢弃尾部、不复活过期指令。
- 红外：按键映射、重复帧、孤立/过期重复帧、只启动一次。
- 硬件适配假 I/O：引脚、电机方向、反向前零输出、舵机启动位置、16 位测距换算、无回波与电压换算。
- 主机：固件识别、应答序号、限时续发、丢失应答/断连/复位时退出和 STOP、只读观察、锁与数据导出。

C++ 原生测试使用固定基准参数，回放使用当前生产配置。校准参数变化后，回放的预期 PWM/时间也需要同步检查。模拟输入与假 I/O 不能检验真实接线、电源、电机摩擦、声波反射和地面光照。

## 已发现的原厂边界

静态检查 `02.2_Ultrasonic_Ranging` 发现其距离数组为 8 位类型，无法完整表达函数设置的 1000 cm 无回波返回值，且会自动扫描舵机。原厂快照保持不变；项目程序改用 16 位毫米值与独立有效标志，无回波退出运行，并已覆盖假 I/O 测试。这是代码审阅与离线验证，不是实车故障报告。
