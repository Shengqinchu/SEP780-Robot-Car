# 安卓语音与蓝牙控制

[English](voice-control.en.md) · [README](../README.md) · [串口协议](control-protocol.md)

## 范围与安全边界

安卓 App 使用套件自带的 BT05/JDY 类低功耗蓝牙串口模块，把有限语音词表转换为现有 `S <seq> ...` 协议。App 不替换车端状态机：超声波障碍停车、低压、传感器故障、指令租约和最大 PWM 仍由 `robot_car` 固件执行。

App 冷启动遥控上限为 PWM 150，滑条提供 110–200、步长 10 的十档范围；下限来自本车“50–100 不能可靠起步”的实测，上限由固件限制。中央模拟摇杆纵轴控制油门、横轴控制转向，使用死区、响应曲线和差速混控。非零主输出从 PWM 110 起步并渐进加速，反向前强制经过零输出。这个上限只作用于摇杆和语音方向，循迹继续独立使用中线 PWM 120 脉冲与 PWM 150 转弯。

- “停止”优先于同一批识别候选中的任何运动词。
- “前进/后退/左转/右转”只运行 1 秒，使用与摇杆相同的原子 `R` 指令和 20 Hz 调度，随后归零。
- “开始循迹”依次发送停车、所选循迹档和 LINE 启动，每 500 ms 发送 `PING`；App 退到后台、断开或退出时停止续租并发送 `STOP`。
- 未识别语句不发送运动命令。摇杆松手或触控被取消时，优先发送 `R 0 0`。
- App 以 20 Hz 产生控制帧，BLE 队列只保留尚未发送的最新摇杆值，避免旧动作堆积。改变遥控上限会先停车；开始循迹不发送遥控上限。
- 按住“鸣笛”发送带租约的蜂鸣请求，松开发送关闭；即使手机失联，车端也会在 1.5 秒内停止。该有源蜂鸣器只能响/停，可做节奏，不能输出可靠旋律音高。
- App 不保存录音；系统语音识别服务可能把音频发送给其服务提供商。BLE 串口本身没有项目级身份验证，只在受控近距离场地使用。

支持的中文词包括“停止、停车、开始循迹、循迹、前进、后退、倒车、左转、右转”；同时接受对应的有限英文词。自由问句、连续对话和开放式自然语言不在首版范围内。

## 构建

首次在 x64 Windows 上运行：

```powershell
./scripts/Setup-Android.ps1
./scripts/Build-Android.ps1
```

工具版本固定在 `android-toolchain.lock.json`。调试 APK 输出到被 Git 忽略的 `artifacts/local/SEP780-Robot-Car-debug.apk`，不会上传仓库。已启用 USB 调试并确认目标手机后才可安装：

```powershell
./scripts/Install-Android.ps1 -ConfirmDeviceReady
```

最低系统为 Android 8.0（API 26）。主页右上角可直接切换“中文 / English”，选择会持久保存，语音识别语言随界面切换，中英文安全命令词表均保留。全部主控件固定在同一页：上方为蓝牙连接和电池/测距/三路循迹指标，状态行右侧为“步进 / 正常”，中间是遥控上限滑条和大面积模拟摇杆，下方是语音、按住鸣笛、循迹和固定急停；无需滚动。摇杆内显示左右轮实时输出。Android 12 及以上会请求“附近设备”，旧版扫描会请求定位；首次语音操作另行请求麦克风。首版不包含 iOS 客户端。

## 首次验收

1. 小车断电，USB 拔下，按丝印方向插回蓝牙模块；不要带电插拔，也不要反插。
2. 四轮架空且周围无遮挡后再开车上电源。App 点“扫描”；只切换本车蓝牙电源，用出现/消失的差分确认目标模块，不依赖公开文档中的固定设备名。
3. 连接后等待遥测出现并先点“停止”。四轮架空，先把遥控上限保持 150，短推摇杆复核前后、差速弯和原地转向；松手必须立即回零。再短按鸣笛，松手后必须停止。
4. 架空通过后，在白底黑线场地先短测“正常”：中线应步进，侧偏应连续修正，单侧位应原地转向；确认方向正确后才跑完整弯道。摇杆上限不改变循迹，只用于后退、左右转等手动/语音动作。
5. 说“开始循迹”，确认循迹；说“停止”，确认立即退出模式。最后加入 20 cm 内平整障碍，确认车端停车和蜂鸣；移至 30 cm 外并保持线路有效，确认恢复。App 只能发送意图，不能绕过车端安全条件。

原厂明确要求上传 Arduino 程序时移除蓝牙模块；重新上传固件仍按[校准指南](calibration.md)执行。最坏情况的 `R` 遥控帧恰好为 20 字节，不需要 BLE 分片；其他长帧仍会分片，完整协议帧继续受 63 字节和 200 ms 接收窗口约束。
